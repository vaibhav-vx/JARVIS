## 📖 Deep Repository Knowledge & Architectural Breakdown

### 1. Loop Engineering (`cobusgreyling/loop-engineering`)
* **URL**: `https://github.com/cobusgreyling/loop-engineering.git`
* **Core Concept**: Autonomous AI engineering relies on non-linear, closed-loop feedback cycles. Every change goes through a strict cycle: `Plan → Execute → Test → Reality Audit → Refine → Re-test`.
* **JARVIS Application**: Never declare a task complete after simply writing code. Run `npm run build`, inspect terminal logs, check runtime state, and perform zero-flattery reality checks before concluding.

### 2. Chrome DevTools MCP (`ChromeDevTools/chrome-devtools-mcp`)
* **URL**: `https://github.com/ChromeDevTools/chrome-devtools-mcp.git`
* **Core Concept**: Real-time integration between AI coding assistants and browser developer tools for instant diagnostic feedback.
* **JARVIS Application**: Inspect console errors, 404 network requests, DOM structure, CSS layout calculations, and Core Web Vitals (LCP, CLS, INP) to ensure 0 browser errors.

### 3. Agent Skills (`agentskills/agentskills`)

### 5. Superpowers (`obra/superpowers`)

## 🛠️ Permanent Execution Protocol

When undertaking any task in this codebase:
1. **Consult `brain.md` & `skills.md`**: Review repository skills, standards, and team role perspectives.
2. **Inspect Source Files First**: Use `view_file` or `grep_search` to verify exact variable names and paths.

4. **Build & Verify**: Run `npm run build` and inspect output to confirm 0 compilation or type errors.
5. **Report Truthfully**: Summarize the changes clearly with zero fluff or brown-nosing.
